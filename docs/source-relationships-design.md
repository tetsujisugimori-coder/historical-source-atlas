# 史料記事間の関連付け・閲覧キャプション設計（提案 v0.1）

- 起案：2026-11-06
- 起点：[Issue #6](https://github.com/tetsujisugimori-coder/historical-source-atlas/issues/6)
- 適用方針：[AGENTS.md](../AGENTS.md)
- 状態：**設計提案（コード・DB移行は未実装）**

## 目的と基本判断

Historical Source Atlasは「出来事を一つにまとめた歴史年表」ではなく、「史料の記事を独立した項目として蓄積し、出典に遡れる年表・地図・比較画面」を目指す。

同一の合戦を『永享記』『鎌倉大草紙』が記す場合も**各史料の記事は別レコード**とする。記事ごとの和暦・原文・人物・地名・戦闘経過・暦換算・解釈を保存する。「関連する記事がある」という発見は記事本体とは別テーブルへ保持する。説明用キャプションを独立データの保存先にはしない。

## 使い分ける関係の種類

| 表示区分（案） | 意味 | 注意点 |
|---|---|---|
| 同一事件に関する記述 | 同じ出来事について記していると根拠付きで判断できる | 「記事内容が一致」と同義ではない |
| 類似する記述 | 人物・場所・行動などが似る | 事件の同一性は未確定 |
| 異説・相違 | 同じ話題について日付・人名・経過・結果などが異なる | 相違点と両記事の表記を併記。原文を上書きしない |
| 前後関係 | 先行・後続と判断した記事同士 | 方向と根拠が必要。記事の掲載順と史実の前後を混同しない |
| 関連候補 | 関連がありそうだが照合不足 | 「確定」と誤読させない |

**実装時の追加検討点：** 上表の「異説・相違」は「同一事件」と同時成立し得るため、単一の排他的ラベルに限定しない設計が望ましい。主関係（同一事件・類似・前後・候補）と相違点（「日付」「人名」など）のタグを分ける選択肢もある。ここでは最終DB形を固定しない。

## 確認状態

関係の状態は少なくとも「関連候補・未照合」「根拠確認中」「根拠確認済み」「保留／対立説あり」を区別できるように検討する。ただし「確認済み」は**関連付けの根拠が確認できた**という意味に限定し、歴史上の出来事の真偽が確定したことを意味しない。

## 関係レコードの項目（将来案）

- 原記事IDと参照先記事ID（どちらも恒久ID）
- 関係の種類（上の区分）・相違点の種類と説明
- 判定の状態と根拠（どの伝本・頁／行・段落・参考文献を見たか）
- 照合者、記録日、更新日、必要なら変更履歴
- 先行・後続の関係では向き
- 重複登録防止（非方向の関係はID組を正規化して保存し、閲覧では双方向に表示する）
- 未確認の根拠を「確認済み」として扱わないためのバリデーション

既存 `prototype/eikyouki/schema.sql` の `article_relationships(article_id_a, article_id_b, relation, evidence_note)` をまず活用する。新しい列・テーブル・制約の追加は別Issueで受入を設計し、既存データを破壊しない移行を行う。

## 閲覧画面のキャプション

記事下部など、本文の表示と混同しない位置に関連リンクを置く。関係データから生成し、表示用文案と研究上の判断を混同しない。

> 関連史料：『鎌倉大草紙』にもこの合戦に関する記事があります。（関係確認中）

> 関連候補：『鎌倉大草紙』の記事が関連する可能性があります。（同一事件か未確定）

> 異説あり：関連する史料記事では日付の記述が異なります。（各記事の原文を比較）

上の文例は**機能説明のための架空例**。『鎌倉大草紙』側の記事を実際に照合・登録したという意味ではない。リンク先の記事IDが存在しない場合は、有効なリンクを捏造しない。

## 将来の比較表示

- 関連キャプション → 関連記事を開く → 必要に応じ左右比較。
- 史料名・版・記事ID・原文日付・暦換算の状態を常に表示。
- 原文と要約、研究者の注釈、関連付けの理由を視覚的に分ける。
- 不一致点を際立たせても、どちらの史料を「正史」とするか自動判定しない。
- 地図上の位置が不明な記事を、見栄えのために推測座標へ配置しない。

## 検証・受入観点（将来実装）

1. 別史料の似た記事を登録しても件数・恒久IDが維持され、元の記事に差分がない。
2. 同一記事への自己参照・存在しないID・非方向関係の重複が防げる。
3. 方向のある「前後関係」を反転表示しても意味が逆にならない。
4. キャプションにリンク先、関連種別、確認状態、根拠表示がある。
5. 関連を取り消しても記事本体が削除されない。
6. 候補と確認済みの状態が表示で混同されない。
7. 既存の『永享記』記事、暦換算、記載事項、ソースリンクの回帰検査が通る。
