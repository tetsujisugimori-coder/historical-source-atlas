# 史料採録と史実認定の分離・歴史的命題の評価方針

- 決定：ユーザー合意（2026-11-09 JST）
- 適用対象：史料採録・史料比較・将来の史実評価／表示機能を扱う人間・AI
- 現状：**運用原則の文書化のみ**。命題DB・判定UI・自動認定は未実装
- 上位ルール：[AGENTS.md](../AGENTS.md)
- 関連設計：[史料記事間の関連付け・表示設計](source-relationships-design.md)

## 0. 必須原則（AIが最初に読む）

1. **史料に記述が存在することと、叙述された出来事が実際に起きたことを別の判断として扱う。** 公開翻刻と一致しても、歴史上の事実の確証にはならない。
2. **史料の採録は史実認定を条件にしない。** 伝聞、誤伝、誇張、後世の創作、相互に矛盾する記事も、出典と性質を明示して独立保存する。
3. **史実評価の対象は史料記事全体ではなく、検証可能な個別の歴史的命題（claim）とする。** 同じ記事に含まれる別の命題には異なる評価があり得る。
4. **原記事の恒久ID・原文・日付・出典・注記を、後からの史実評価で上書き／統合しない。** 命題と記事は別レコードで関連付ける。
5. **不確実性と反証を保全する。** 根拠不足、史料間の相違、伝本の異同は消さない。判定には理由・根拠の特定情報・判定者・日付・履歴を付す。
6. **テスト成功・翻刻照合・暦換算一致・関連付け確認・公開状態を根拠に史実認定を自動昇格しない。** 未確認は未確認と書く。
7. **同じ事件を扱う複数史料の記事も統合しない。** 関連は別管理とし、複数の文献が同一の情報源に依存している可能性を検討する。
8. **既存スキーマや表示へ勝手に実装しない。** 本文書は方針であり、テーブル・API・UIの実装には別Issue/PRで仕様・移行・検証を設ける。

## 1. 評価対象を分ける

| 対象 | 確認する問い | 史実認定との関係 |
| --- | --- | --- |
| 史料記事（article） | どの史料・伝本・版の、どの範囲に、何が書かれているか | 採録は独立に進める |
| 記述の照合（textual verification） | 公開翻刻、底本画像、写本・異本をどこまで確認したか | 記述の存在や校訂の検証であり、事件の真偽ではない |
| 記事間の関連（article_relationships） | 別の記事が同一事件・類似・異説・前後関係を記すか | 関連が確認されても真偽は確定しない |
| 歴史的命題（historical claim） | 例えば「特定の日に特定の場所で包囲が起きた」という判断はどの程度支持されるか | **史実評価の基本単位** |
| 研究上の支持状況（scholarly consensus） | 専門研究で通説か、異説があるか、研究未確認か | 命題の証拠評価とは**別の軸** |

**独立性**は「別の書物に書いてある」と同義ではない。後発史料が先行史料を引用・翻案している場合は、裏付けを重複計上しない。

## 2. 史実命題の5つの検討軸

1. **成立・伝来・真正性**：作成者、成立時期、原本／写本、伝来、改変や後世の加筆可能性、底本・伝本の照合状況。
2. **記述の性格・信頼性**：同時代性、目撃／伝聞／編纂、叙述意図、立場・利害、誇張・修辞・推量の有無。
3. **証拠の独立性・照応と不一致**：異なる証拠系統による裏付け、引用関係、具体的な一致点・相違点、反証。
4. **年代・地理・物的証拠との整合**：暦・場所・移動可能性、古文書、遺構・遺物など。ただし暦計算の正しさは事件日付の真実性を示さない。
5. **先行研究の検討**：研究上の解釈、通説・少数説・反対説、論拠の妥当性、研究の時期と未確認資料。

判定は**単純な点数・証拠件数・AIの多数決で自動決定しない**。同時代の強い一次証拠が1件のみという場合もあり、複数の見かけ上の証拠が同じ伝聞に依存する場合もある。

## 3. 将来用の状態モデル（今はDB未実装）

少なくとも次の**別軸**を区別する。ラベルは将来の実装時に別途検討し、既存記事に自動付与しない。

### A. 記述照合の到達範囲
- `not_checked`：当該範囲の照合なし
- `public_transcription_checked`：固定版などの公開翻刻で照合済み
- `base_image_checked`：特定の底本画像と照合済み
- `variant_comparison_checked`：特定した伝本間の異同を比較済み（対象と範囲を記録）

この軸は一律の「完成度」ではなく、**どの資料・どの箇所を確認したか**を必ず添える。

### B. 歴史的命題の評価
- `unassessed`：史実評価をまだしていない
- `indeterminate`：検討したが根拠不足で判断保留
- `supported`：出典の批判的検討により相応の支持がある
- `strongly_supported`：強い証拠と反証検討を経て高い確度と判断
- `disputed`：重要な証拠や解釈が対立している
- `refuted`：対象命題への強い反証が確認された（反証内容を明記）

これらは**研究上の判断を説明するための案**で、世界共通の公式な史実等級ではない。`supported` や `strongly_supported` を「絶対に確定」と表現しない。`disputed` と `indeterminate` を単なる低得点扱いしない。

### C. 研究上の受容状況
- `not_reviewed`：関連研究を十分に調べていない
- `mainstream`：調査した研究範囲で通説として広く支持される
- `contested`：研究上の有力な論争がある
- `minority_view`：調査した研究範囲では少数説として扱われる
- `unclear`：研究状況を確定できない

「通説」はB軸の上位レベルではない。どの研究を、いつ、どこまで調べたかを併記し、新研究で変更可能にする。

## 4. 将来の概念データ例（未実装・架空の評価）

`claims`、`claim_article_links`、`claim_evidence`、`claim_assessments` のような**別レコード群**を検討する。既存 `articles` と `article_relationships` を置換しない。下記は概念例であり、実在のDB行でも史実認定結果でもない。

```yaml
# conceptual example only / not a registered claim
claim_id: EXAMPLE-CLAIM-001
proposition: "永享十一年二月十日に永安寺の包囲があった"
article_refs: ["EK-0042"]
date_assertion: "本文では永享十一年二月十日"
date_interpretation: "記事の日付がどの範囲の行為に及ぶかは別途評価"
textual_verification: "public_transcription_checked"
historical_assessment: "unassessed"
scholarly_consensus: "not_reviewed"
evidence_refs: []
independence_review: "not_checked"
counterevidence: []
assessed_by: null
assessed_at: null
reason: "公開翻刻の採録と暦換算は行ったが、史実の裏付けを独立評価していない"
```

実装時には、各証拠の具体的な版・巻・頁・行・URLまたは所在、取得・照合時刻、異本、依存関係、支持／反証の向き、研究文献情報、判定履歴・版を失わない構造にする。採録時の記事IDは永続させ、命題と史料記事の関係は多対多とする。

## 5. 評価の手順

1. 個別に真偽を問い得る命題を切り出し、原記事ID・原文位置を結び付ける。複合命題（事件発生・日付・場所・経緯など）は必要に応じて分ける。
2. 記述の照合済み範囲と未照合範囲を分けて記録する。底本未見なら底本未照合と明記する。
3. 5検討軸で支持証拠・反証・引用依存・研究解釈を記録する。支持と不一致のいずれも隠さない。
4. 「歴史的命題の評価」と「研究上の受容状況」を別々に判断し、根拠不足なら保留する。
5. 判定者・日付・参照資料と理由・未確認事項・旧判定を保存し、後の更新は上書きで履歴を失わせない。
6. 表示では「史料によれば」「記述確認済み」「史実評価未実施」「有力説」「異説あり」等を区別する。原文と現代の評価を混ぜない。

## 6. 『永享記』第7便の扱い

- `EK-0042`：本文「永享十一年二月十日」の記述確認と国立天文台による暦日照合があっても、「同日の永安寺包囲が歴史上実際に起きた」という命題は**未評価**。
- `EK-0043` と `EK-0044`：前記事との叙述上の連続性から、自動で二月十日や場所を確定しない。
- `EK-0045`：回顧的叙述を掲載順と同じ出来事の順序と見なさない。
- `EK-0046`：「同廿八日」の年・月の文脈補完、暦換算、事件発生日の評価は別々。
- 例として「持氏が自害した」と「自害の具体的経過が史料どおり」は**別命題**。それぞれ独立して証拠評価する。
- 現在の第7便は仮登録記事の技術整合を確認した段階であり、底本画像、異本、系譜、史実認定は未検証と明示している。文書の追加でこの判定を変更しない。

## 7. 変更時の受入条件

- [ ] AIが「本文に書いてある」だけを理由に史実と断定しない
- [ ] 記述照合、史実の支持度、研究上の通説性が別軸で保持される
- [ ] 支持・反証・未確認・史料依存・判定根拠を出典に戻って点検できる
- [ ] 一記事に複数命題、一命題に複数記事を関連付けても記事原本とIDが変化しない
- [ ] 時間・人物・場所を未検証なのに自動補完しない
- [ ] CI・ブラウザ検証や公開だけで史実評価が昇格しない
- [ ] DB・API・UIは別Issue/PRとし、移行・回帰検査を実施する

この文書は**史実を認定した記録ではなく、今後の認定方法についての合意**である。
